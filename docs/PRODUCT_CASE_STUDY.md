# 产品案例复盘

## 问题

传统背词软件擅长安排重复和建立中英对应，却很难解释近义表达之间的细微边界。用户可能知道 `keep`、`maintain` 和 `preserve` 都与“保持”有关，却仍然不知道在翻译、作文、交流或阅读中应该怎样选择。自由笔记可以记录细节，但整理成本高，也很难持续维护结构。

与此同时，每个人在课程、外刊、书籍、影视和真实交流中遇到的词并不相同。固定词典无法反映这种个人路径；直接让 AI 批量写入，又会带来生成不稳定、内容污染和关系失控的问题。

## 产品判断

本项目把“核心表达辨析”作为学习中心：多个相近表达必须在同一上下文中比较语义、语域、搭配和使用场景。AI 负责按用户实际遇到的词生成候选内容，用户负责审阅和最终判断，因此词典会沿着个人外语知识的形成过程逐步生长。

知识图谱也不是装饰性的全局关系图，而是围绕当前词展示可筛选、可展开、可迁移的局部语义网络，让用户看到一个词如何与已有知识连接。

## 从需求到实现

| 产品问题 | 设计选择 | 工程落点 |
| --- | --- | --- |
| 相近词都能翻译成同一个中文，实际不会选 | 把全部核心表达放进同一辨析板 | 统一呈现核心区别、易混点、搭配和例句 |
| 每个人遇到的词不同 | 遇到新词时再由 AI 生成 | 后台生成队列与个人本地词库 |
| 内容太多，复习没有重点 | 高频、阅读、低频作为复习层次 | 统一卡片模型与中英文两套渲染规则 |
| AI 可能生成错误内容 | 生成后必须审阅 | 临时任务、结构校验、新旧对比、逐条决策 |
| 图谱关系多，颜色会失控 | 颜色服从主题，类别依靠筛选 | 关系类别配置与图谱视觉解耦 |
| 大图谱拥挤且难理解 | 只展示当前词附近云团 | 局部图谱、关系展开、中心词迁移 |
| 用户担心数据被锁定或损坏 | Markdown 本地优先、写前快照 | 单一写入核心、外部备份、恢复后重建索引 |
| 多个平台导词方式不同 | 先定义统一接入队列 | 粘贴/TXT/CSV 可用，第三方平台走适配器 |

## 迭代中解决的代表性问题

- 搜索输入卡顿：把高频输入更新与昂贵解析解耦，并保留界面状态。
- 图谱节点“躲鼠标”：区分自由拖拽阶段和关系展开后的固定布局。
- 图谱连线与节点断开：统一节点几何坐标和边的渲染坐标。
- 首次展开与第二次不一致：让中心词迁移、关系展开和布局初始化共享同一状态入口。
- AI 结果直接污染词库：建立完整审阅协议，最终确认前不触碰正式数据。
- 桌面发布路径混乱：形成安装版、免安装版、旧版回退和版本号一致性检查。

我负责提出问题、确定“词义辨析优先”的产品方向、规划交互与数据边界，并对每轮实现进行验收；生成式 AI 参与需求推演、原型与代码实现、演示内容生成和问题排查。这个协作方式本身也是项目能力的一部分：重点不是回避 AI，而是能够提出准确问题、拆分任务、约束输出，并把 AI 产出整合成可验证、可交付的软件。
