# 产品案例复盘

## 问题

背词软件擅长安排重复，但通常只展示单词和释义；自由笔记能记录细节，却很难持续维护结构。加入 AI 后，新问题变成：生成内容不稳定、批量写入风险高、不同词之间的关系越来越难浏览。

## 产品判断

本项目没有把 AI 当作主界面，而是把“复习界面”作为产品中心。AI 负责降低整理成本，用户仍然控制最终内容。知识图谱也没有追求一次展示全部数据，而是围绕当前词提供有限、可交互的局部关系。

## 从需求到实现

| 产品问题 | 设计选择 | 工程落点 |
| --- | --- | --- |
| 内容太多，复习没有重点 | 高频、阅读、低频、核心辨析分层 | 统一卡片模型与中英文两套渲染规则 |
| AI 可能生成错误内容 | 生成后必须审阅 | 临时任务、结构校验、新旧对比、逐条决策 |
| 图谱关系多，颜色会失控 | 颜色服从主题，类别依靠筛选 | 关系类别配置与图谱视觉解耦 |
| 大图谱拥挤且难理解 | 只展示当前词附近云团 | 局部图谱、关系展开、中心词迁移 |
| 用户担心数据被锁定或损坏 | Markdown 本地优先、写前快照 | 单一写入核心、外部备份、恢复后重建索引 |
| 多个平台导词方式不同 | 先定义统一接入队列 | 粘贴/TXT/CSV 可用，第三方平台走适配器 |

## 迭代中解决的代表性问题

- 搜索输入卡顿：把高频输入更新与昂贵解析解耦，并保留界面状态。
- 图谱节点“躲鼠标”：区分自由拖拽阶段和关系展开后的固定布局。
- 图谱连线与节点断开：统一节点几何坐标和边的渲染坐标。
- 首次展开与第二次不一致：让中心词迁移、关系展开和布局初始化共享同一状态入口。
- AI 结果直接污染词库：建立完整审阅协议，最终确认前不触碰正式数据。
- 桌面发布路径混乱：形成安装版、免安装版、旧版回退和版本号一致性检查。

## 能力证明

该项目展示的不只是页面实现，还包括：

- 从模糊想法提炼核心工作流与版本边界。
- 在多轮反馈中保持数据协议和视觉规则一致。
- 将 Python 既有能力迁移到 Electron 桌面架构。
- 处理本地文件、IPC、子进程、异常恢复和 Windows 打包。
- 为复杂交互建立自动化测试和人工验收清单。
- 在公开展示、用户隐私和未来商业化之间划定边界。
